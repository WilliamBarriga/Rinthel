# Deck: configuration

Deck is the Instance's web portal. It runs as a managed service from the root compose project (`name: rinthel-general`, `include: deck/docker-compose.yml`), and reads the root `.env` only: there is no `deck/.env`.

## What it reads

| Variable | Default | Meaning |
| --- | --- | --- |
| `RINTHEL_DECK_PORT` | `4100` | Port Deck listens on (host network on Linux; published on `127.0.0.1` on Windows). |
| `RINTHEL_DECK_ENABLED` | `true` | Whether BOOT/TERMINATE/RELOAD manage Deck and the daemon retires a user's Sessions in it before deleting the user. |
| `RINTHEL_PANEL_SECRET` | none | Signs the Panel tokens; the daemon signs with the same one. Generated by INSTALL. Without it Deck refuses to start: there is no open mode. |
| `RINTHEL_SERVICE_SECRET` | none | What the daemon sends to `POST /api/agent/retire-sessions`, and what Deck sends to read a user's live role. Generated by INSTALL. |
| `RINTHEL_DAEMON_PORT` | `8765` | Where Deck reaches the daemon, on the host loopback. |
| `RINTHEL_HOSTEXECD_URL`, `RINTHEL_HOSTEXECD_TOKEN` | set by the daemon | How an admin's Session reaches `hostexecd` (Linux only). The daemon passes both when it brings Deck up, the URL built with `deck.host_address`. Without a token no Session has host exec; with one, a URL that cannot register stops an admin's Session from starting. See [`../07-host-exec.md`](../07-host-exec.md). |
| `UNDERSTORY_TOKEN` | none | Understory's token (the root `.env`'s, the one Understory gets as `AUTH_TOKEN`). Set, an admin's Sessions get the Memoria; unset or blank, no Session has it. The URL comes from the daemon's routing. See [architecture](architecture.md#memoria). |
| `DECK_DB_JOURNAL_MODE` | `wal` | `delete` where WAL cannot work on the bind mount (Windows). |
| `DECK_SLOTS_MAX_GB` | `20` | What the Sessions' saved slots of the local LLM may hold in all; past it the least recently used are deleted. |
| `WORKSPACE_ROOT` | `/data/workspaces` | The Instance's workspaces, where an admin opens task Sessions. |
| `PORTAL_EVENT_RETENTION_DAYS` | `90` | How long a Session's event log keeps what pi emitted. |
| `PORTAL_TLS_CERT`, `PORTAL_TLS_KEY` | empty | Serve Deck over HTTPS when both are set and exist. |
| `PUID`, `PGID` | `1000` | The container user, so what Deck writes under `data/deck` stays the host user's. INSTALL writes the host user's ids on Linux. |
| `DOCKER_GID` | the user's group | The host's docker group, so Deck may use the Docker socket mounted for the Instance browser. INSTALL writes it on Linux. |
| `VOICE_PIPELINE_MODE` | `parallel` | `sequential` reads a whole reply before it speaks (a baseline to compare against); `parallel` synthesizes the next phrase while the last one plays. |
| `VOICE_SENTENCE_CHUNKS`, `VOICE_TTS_PREFETCH` | `false` | In `sequential` mode, speak sentence by sentence, and prepare the next one ahead. |
| `VOICE_STATUS_SPEECH` | `true` | Short spoken notices while the Agent thinks or compacts. |
| `VOICE_COMPARISON` | `false` | Labels the voice stage with the pipeline in use, for side-by-side comparisons. |
| `VOICE_RESPONSE_INSTRUCTIONS` | `true` | `false` leaves out the speaking rules and the `[Audio mode]` marker of a voice Turn. |
| `VOICE_SKIP_FIRST_THINKING` | `true` | The first model call of a voice Turn runs without thinking, so the first words come sooner. |
| `BROWSER_CDP_URL` | `http://127.0.0.1:9222` | The Instance browser's fixed CDP endpoint, which every admin Session that may drive it shares. |
| `BROWSER_EXTERNAL` | `false` | `true` for a browser started and stopped outside Deck: Deck only finds it over CDP and refuses to install, start or stop it. |
| `BROWSER_MCP_COMMAND` | `npx -y @playwright/mcp@0.0.79` | The Playwright MCP server that drives the browser (pinned); Deck adds `--cdp-endpoint` and `--snapshot-mode none`. |
| `BROWSER_USER`, `BROWSER_PASSWORD`, `BROWSER_PORT`, `BROWSER_HTTPS_PORT` | `agent`, none, `3010`, `3011` | The browser view's login and ports until an admin saves their own from the Instance browser screen. |
| `BROWSER_VOLUME`, `DOCKER_SOCKET`, `BROWSER_BINARY`, `BROWSER_HOST`, `BROWSER_STREAM_PORT` | `deck_browser-profile`, `/var/run/docker.sock`, none, `127.0.0.1`, `8082` | The container's profile volume (its logins), the socket, a Chrome to try first in local mode, where the view and the stream the frame keeper watches listen, and that stream's port. |
| `BROWSER_NETWORK` | `host` | The `deck-browser` container's network. `host` on Linux; on Windows the override names the user network Deck shares with it, and the browser's CDP listens on that network (never published). |

On Windows `compose/windows.override.yaml` sets `RINTHEL_DAEMON_URL`, `DECK_DB_JOURNAL_MODE=delete`, `BROWSER_NETWORK`, `BROWSER_CDP_URL` and `BROWSER_HOST`, drops `PUID`/`PGID`/`DOCKER_GID`, and publishes the port on `127.0.0.1` only. See [`../04-windows-installation.md`](../04-windows-installation.md).

The daemon reads `RINTHEL_DECK_PORT`, `RINTHEL_DECK_ENABLED` and the service secret once, at startup: after changing them, restart the daemon as well as Deck.

## State

Everything Deck keeps lives in `data/deck/`, mounted at `/data`:

- `deck.db`: Sessions (with their events and notes), Canvases and settings, in SQLite (`better-sqlite3`, WAL; DELETE on Windows). The journal mode in use is in the startup log (`store: … (journal mode wal)`); a mode SQLite does not take stops the start. Migrated when Deck starts (`PRAGMA user_version`); a file at a newer version than the code, or SQLite older than 3.37, stops the start with a clear error.
- `home/`: `HOME` of the container, so pi's `agentDir` is `data/deck/home/.pi/agent`.
- `sessions/<id>/`: each Session's pi files, so a Session reopens its exact conversation after a restart. Deleted with the Session.
- `users/<id>/agent/`: an owner's Agent home, where their `agent` Sessions work; `SOUL.md`, `PrimaryUser.md` and `MEMORY.md` there are the Agent's own context.
- `users/<id>/workspaces/`: a member's workspaces. An admin's task Sessions use the Instance's (`WORKSPACE_ROOT`, `data/deck/workspaces`).
- `instance/SOUL.md`: the Instance SOUL, the `SOUL.md` every member's Sessions load as their own (read-only for them, edited by an admin from the SOUL screen). INSTALL seeds it from a template once and never overwrites it; an admin's own `SOUL.md`, in their Agent home, is not touched.
- `llama-slots/`: llama-server's `--slot-save-path` (the daemon passes it). Deck restores a Session's slot before each call to the model and saves it after; the files are named by owner, Local model and Session, and go with the Session.

Users are not in `deck.db`: they live in the daemon's `rinthel.db`. A Session keeps its owner's id as a plain column, and the daemon calls `POST /api/agent/retire-sessions` before deleting a user (ADR 0007).

## Login

A user logs in with their username and password; the daemon checks them and issues a Panel token, which Deck keeps in two HttpOnly cookies (access and refresh). The access token is validated locally; when it expires, Deck refreshes it with the daemon inside the same request, and the refresh token rotates. Every admin route reads the user's role again from the daemon, so a demoted or disabled user loses access on their next request. Only an Admin sees and uses the Usuarios screen.

## Chat

Each Session runs pi in Deck's process through pi's SDK. An admin's Agent is the general one (pi's built-in tools, the extensions and skills of the `agentDir`, and on Linux the host exec tools `rinthel_host_exec` and `rinthel_host_exec_history`, whose every call checks again that the owner is an admin, and the `subagent` tool, which hands a task to a child agent on the same Local model; see [architecture](architecture.md#subagents); and the Instance browser's tools, below); a member's is closed: nothing of pi is loaded from disk and its only tools are the canvas ones (`canvas_list`, `canvas_create`, `canvas_read`, `canvas_write`, `canvas_delete`), and its SOUL is the Instance SOUL. Every Session runs with the Guard, which marks a Session tainted after it reads untrusted output (network commands in `bash` or `rinthel_host_exec`, MCP, the Instance browser's tools, a subagent's answer). A tainted Session loses host exec, `subagent` and Memoria writes outright and is refused the dangerous shapes of a call (fixed `RULES`). Every call the Guard checks is a `portal_guard` event in the Session's log (`allow` or `deny`); the transcript shows the refusals. The taint is kept in `deck.db` (`session_taint`) and rebuilt when the Session's pi starts, which starts tainted until then: a Session that restarts, or whose pi file is gone, stays tainted.

The model is the Instance's Local model (ADR 0008). On every call the Session's proxy asks the daemon for the route (`GET /model-provider/routing`) and goes straight to llama-server, asking for prefill progress. The context window pi plans by comes from the route. At its first prompt a Session with an owner tells the Agent who it belongs to (name and role), or that an admin supervises it.

Only an admin changes the Local model, from the composer or from Ajustes. Deck refuses with `409` while any Session is generating, and the daemon refuses with its own `409` while another lifecycle command runs or llama-server is processing. A Session finds out on its next call: the proxy answers `wrong_model`, and the turn goes on with the new model.

## Instance browser

One browser per Instance, signed into the Agent's accounts and kept that way by its profile. It runs in one of three modes: docker (the `deck-browser` container, `lscr.io/linuxserver/chromium`, host network on Linux, a user network shared with Deck on Windows, its profile in the `deck_browser-profile` volume), which Deck installs over the Docker socket; a local Chrome or Chromium when there is no socket (its profile in `data/deck/browser-profile`); or external (`BROWSER_EXTERNAL=true`), which Deck only finds over CDP. It is not a compose service: nothing exists until an admin installs it.

Only an admin sees and administers it, from the Instance browser screen: install (refused in docker mode until it has a password; a random one can be suggested), start, stop, remove (the logins stay; forgetting the profile is separate), the allowlist of domains (globs such as `*.example.com`; empty means no restriction), the Sessions that may drive it, and its live view. The view is the browser's KasmVNC page, proxied by Deck at `/browser-ui` (HTTP and websocket) with the browser's password added by Deck; a member, or a demoted or disabled admin, is refused. While nobody watches the view, Deck keeps the stream open at a low frame rate so the page keeps rendering and clicks keep working. Nothing stops the browser for being idle: it runs until an admin stops it.

The Agent drives it with Playwright's tools, registered inline in the Session (no `mcp.json`) and run by the pinned Playwright MCP server over the fixed CDP endpoint. Every Session shares that one process and its tabs, with no lease. Only an admin's Session gets the tools, and each call goes through two gates: the Session's toggle (`sessions.browser`, set by an admin from the chat's browser panel or the API) and the owner's role, read from the daemon on every call; an owner that is not an admin now, or a role that cannot be read, is a refusal. A member's Session never has the tools, whatever its toggle says. The Guard refuses any other browser tool (another MCP's, or the adapter's proxy), the tools that run arbitrary code or read Deck's files (`browser_run_code_unsafe`, `browser_file_upload`, `browser_drop`) are never registered, and what the browser returns taints the Session.

## Voice

Any user talks with the Agent by voice in their own Sessions, hands-free: the browser detects when they speak (Silero VAD, run in the page), Deck transcribes each turn with the Instance's `stt` Local model (whisper-server), sends it as a voice Turn, and reads the reply aloud with the `tts` Local model (audiocpp-server), phrase by phrase while it streams. Speaking over the reply interrupts it. While the person talks, a live transcription previews what was heard. The stage also shows the prompt's reading and a compaction in course, the Agent's tool calls, a latency profiler and cue sounds; mute keeps the reply playing.

Voice appears only when the reader turned it on (Voz screen) and the Instance has both `stt` and `tts` active (`[models] stt`, `tts` in `instance.toml`; INSTALL `--voice` adds them, Linux only; an admin turns each one on with a catalog entry, or off, in Ajustes, which calls `POST /api/models/activate` or `POST /api/models/off` and the daemon starts or stops the service). Without them the microphone button is not there: no error. Each user keeps their own settings in `deck.db` (`voice:user:<id>`): whether voice shows in their Sessions, the input language (or auto-detection) and the speech detection (end-of-turn silence, thresholds, minimum speech, audio kept before speech).

Deck goes straight to the services on the daemon's route (`GET /model-provider/routing`, read on every call), with no voice route in the daemon (ADR 0008). The TTS speaks in its Local model's fixed voice (`voice` of the catalog entry). Only the Session's owner reaches `/api/sessions/:id/voice/*`: someone else, an admin too, gets a `403`. A voice Turn carries the `[Audio mode]` marker and one fixed system rule tells the Agent to answer in short plain speech and put long content in a Canvas.

The browser needs the microphone over HTTPS or on localhost. The VAD's model and its WebAssembly runtime are copied from `node_modules` into `web/public/voice-assets/` (ignored by git) before every `dev` and `build`.

## Surfaces

The Agent writes Canvases for the person, who only reads them: a `markdown` canvas is a document and a `ui` canvas is an interface built from a closed catalog (headings, text, tables, cards, buttons and form fields). Filters, fields and `setState` are local to the browser; the only action that leaves it is `askAgent`, which leaves a message in the Session that the Agent reads with the next prompt (a click never starts a turn). Canvases stay in memory until stored, and a write in flight when the server dies is marked interrupted on the next start.

Appearance and Personalization (style, reading, panels, saved profiles per user; brand and shared palette for admins) are stored in `deck.db` settings. The SOUL screen shows the Instance SOUL to everyone and lets only an admin edit it.
